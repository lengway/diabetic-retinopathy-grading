# 9. План верификации и оценки

Версия 0.2, 20.10.2026. DIP-11. План экспериментов; обучения, измеренных метрик и пользовательских испытаний в этой версии нет.

## Данные и предотвращение утечек

Первый baseline использует APTOS 2019. EyePACS — расширение после проверки доступа и прав. IDRiD и Messidor-2 резервируются для внешней оценки: на них не подбираются предобработка, веса, пороги и температура. Таблица происхождения и условий — docs/data-plan.md.

E01: построить манифест (source, image_id, patient_id если доступен, label, SHA-256, размеры, split). Проверить повторные файлы по SHA-256, визуально близкие — перцептивным хешем и ручной проверкой. Группировать оба глаза и визиты одного пациента. Сначала выделить группы, затем стратифицированно разделить: train 70%, tuning 10%, calibration 10%, test 10%; seed=42. При малом числе пациентов допускается заранее документированная корректировка пропорций, до любых метрик. Если patient_id неизвестен, не заявлять разбиение по пациентам; это существенное ограничение и источник завышения качества.

E02: зафиксировать test и внешние манифесты до обучения. Предобработка, class weights и sampler вычисляются только по train. Tuning используется для гиперпараметров и ранней остановки. Calibration — для температуры и порога, не для весов. Внешние наборы не входят ни в один этап подбора. Перед внешней проверкой проверить совпадения с обучающими наборами. Внешние данные не становятся клинической валидацией.

## Baseline и сравнение

E03: наивный baseline предсказывает частоты классов train; CNN baseline — EfficientNet-B0, ImageNet-веса, 384x384, cross-entropy, AdamW, до 30 эпох с ранней остановкой по tuning QWK (patience=5). Начальные гиперпараметры: lr=1e-4, weight_decay=1e-4, batch=16 или максимальный в памяти с записью изменения. Аугментации только train; никаких случайных преобразований в test. Дополнительное сравнение — ResNet50 на том же split и разрешении, seed 42/43/44. Время, потребление памяти, версии и стоимость записываются фактически.

Изменять по одному фактору: weighted loss, разрешение, порядковая постановка. Каждое изменение сравнивается с фиксированным baseline. Веса класса — только по train. Размер экспериментов ограничивается бюджетом; при нехватке ресурсов сначала завершить один воспроизводимый baseline. RETFound — литературная альтернатива, не обязательная реализация.

## Метрики и неопределённость

E04: основная метрика — quadratic weighted kappa (порядковые классы 0..4), дополнительно macro-F1 и матрица ошибок с численностью. Для бинарной задачи истинная метка y>=2; score=p2+p3+p4. Измеряются AUROC и AUPRC. Порог выбирается только на calibration: среди порогов с specificity >= 0,90 выбрать максимальную sensitivity, при равенстве — большую specificity; правило перебора и обращение с равными score фиксируются в коде. На test сообщить фактически достигнутые sensitivity и specificity с тем же порогом; не утверждать, что specificity останется 0,90. Предсказанный grade и бинарный флаг могут различаться, поскольку argmax и сумма вероятностей решают разные задачи.

Temperature scaling: подобрать T>0 на calibration по multiclass NLL. Сообщить NLL, Brier score, top-label ECE до и после: 15 интервалов равной ширины, ECE=сумма (доля интервала * |accuracy - mean confidence|). Для бинарного score отдельно показать reliability diagram и binary ECE. ECE зависит от биннинга и не гарантирует надёжность каждого ответа.

E05: 95% percentile bootstrap CI по 2000 повторных выборок пациентов; при неизвестных patient_id — по снимкам с явным указанием ограничения. Для AUROC пропускать вырожденные повторные выборки без одного из классов и сообщать их число. Сравнение моделей — парный bootstrap на тех же наблюдениях; не смешивать разброс seed и CI выборки. Для IDRiD/Messidor-2 сообщить отдельные метрики, drop относительно внутреннего test, распределения классов и камеры, если известны. При несовпадении шкал сначала описать mapping; не придумывать пятистадийную разметку. Если нет подходящей разметки, соответствующая метрика не вычисляется.

## Проверка объяснимости

Выбрать удачные и ошибочные примеры каждого класса, в том числе переуверенные ошибки. Grad-CAM строить для предсказанного класса; сравнить с закрытием значимых областей. Обсудить карты с консультантом после получения согласия; качественное мнение не заменяет количественную проверку и не доказывает причинность карты [L04].

## Критерий завершения этапа

Сохранены код, манифесты, конфигурации, веса с контрольной суммой, отчёты всех запущенных экспериментов и ограничения. Отрицательный результат также публикуется. Цель QWK >= 0,85 считается достигнутой только по фактическому внутреннему test; порог клинической применимости этим не устанавливается.
